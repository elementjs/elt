# elt — TODO

Open items carried over from specs that were folded into `docs/md/` and deleted. Object editor items live in `specs/TODO.md`, and the open questions of the October 2026 audit of the editor in `specs/audit-2026-10-editor.md`.

## elt/ui

- [ ] **Editor grid ARIA.** `role="grid"` on the composite grid, `row` on `e-grid-row`, `rowheader`/`columnheader`/`gridcell` on the cells, `aria-rowcount`/`aria-rowindex` for the windowed rows. Set by the editor's grid code, not by `e-grid`. Keyboard navigation between cells is a later step (roving focus, edit mode vs navigation mode).
- [ ] **Multi-select readability.** Re-check the selected-row treatment (tint surface + 3, docs/md/ui-theme.md#state) once a real multi-select widget exists: "reads fine in principle" isn't guaranteed to survive five selected rows on screen.
- [ ] **Overflow menu for bars.** A decorator that moves the actions that don't fit in a bar into a "…" menu as the window narrows (measured with a `ResizeObserver`, actions ordered by priority). Today the docs tell apps to choose the menu's actions when designing the bar (docs/md/ui-layout.md#bars).
- [ ] **Editor bars vs. the emphasis model** (docs/md/ui-theme.md#emphasis). `editor/shell.tsx`: every editor's header line is tint-inverted, so nested editors stack several tint bands on one screen; a nested one should probably be a neutral surface. `editor/schema.tsx`: the table header is on `tint-2`, which is furniture on tint; should be `neutral`. `editor/composite-toolbar.tsx`: a row with a button and a search field on a `neutral-1` band: acceptable as a secondary bar, check it once the above are settled.
- [ ] **Packed containers, open points.** `seams="children"` doesn't deduplicate lines across nested groups or in grids; a hidden first or last child of a framed container still doubles the line next to the frame (use `If`); the corners of a nested group's children that face a sibling group keep their own radius. To review visually: frameless packed containers that relied on the old lines (`ui/select.tsx`, the docs nav, `docs/src/code-example.tsx`, the examples of `verbs.md` and `ui-typography.md`) now draw none and may want `border="none"` or a frame.
- [ ] **Overlay elevation, to tune.** The values (3/16px, 0.36 total opacity, 1.8 dark) are first guesses to tune by eye; check in a real app whether popups with scrolling content repaint slower with `drop-shadow` than with `box-shadow` (headless: chained `drop-shadow` about 18-27% more per repaint; swapping is local to `ui/popup.tsx`); the dark scheme's light edge if dark popups still look flat; the dialog backdrop is still `rgba(0,0,0,0.5)`, and the docs' nav backdrop `rgba(0, 0, 0, 0.4)` (`docs/src/app.tsx`, disabled with `theme-colors`): a scrim color in the theme would serve both.
- [ ] **Date field, AM/PM width and empty AM/PM.** The AM/PM part is always 2 characters wide, so longer texts are cut (es-MX `a.m.` shows `a.`, ms `PTG` shows `PT`, ne `पूर्वाह्न`); an empty AM/PM part (`--`) reads as AM, so a 12-hour field is never incomplete because of it. Proposed: the part is as wide as the longest of the two texts in the locale, and an empty one makes the field incomplete.
- [ ] **Date field, digits of other scripts.** Digits typed in other scripts (ar-EG `٠٨`, fa, hi…) are not accepted. Proposed: map any Unicode decimal digit (`\p{Nd}`) to its value in the per-character path; check whether the field shows its own digits in that script.
- [ ] **Date field validity to an observable.** `ui/date-input.ts` sets its validity with `setCustomValidity` but has no `o_error` to read it from, as `$bind`'s `BindOptions` gives (docs/md/decorators.md). Then the editor's scalar factories (`editor/schema.tsx`) can pass `BindOptions` and forward native constraint attributes (`min`, `max`, `pattern`, `required`, `step`).
- [ ] **Select button `align-items: baseline`** (`ui/select.tsx`, `cls_select_button`): the audit of October 2026 marked it for removal with a visual check.

## Hard-don't follow-ups

- [ ] **Alerts.** To design: they need a container (an alert host) to be `show`n in; how `show_alert` finds it is open.
- [ ] **Editor CSS that elt/ui could provide.** Each is a class the editor has to write only because elt/ui has no equivalent; `ui/` changes need the user's go-ahead.
  - **Menu items and menu section titles** (`.oe-menu-item`, `.oe-menu-header`, `.oe-menu-danger`, and `text-align: start` of `.oe-text-fill` inside a button). The docs' own menu example (`ui-overlays.md`) is a column of `role="menuitem"` buttons whose labels elt/ui centers; every menu then needs start alignment and an icon/label gap. Candidates: a start-aligned menu item look with a `nudge-4` gap (from `e-widget` or `e-emphasis`, not from the role: docs/md/elt-ui-rules.md, Controls rule 5); a section-title element for menus (small, faded, not selectable, no margin); a danger variant for buttons (red text and red hover, today `theme.colors.red.class_as_tint` plus `color: red`).
  - **Bounded scroll area** (`.oe-grid-scroll`: `max-height: 24em; flex-grow: 1`, for the windowed composites). `max-height` takes only a boolean (`100%`), and `grow` sets `flex-basis: 0`, which collapses a scroll area in a column of no set height. Candidates: a `max-height` that takes a length (or a `--e-scroll-max-height` variable); a `grow` that keeps the content-sized basis.
  - **Truncating text** (`.oe-text-fill`, the filter field and the preview in a button). `e-ellipsis` does most of it but does nothing for the left alignment inside a button (see the menu item candidate). Candidate: check whether `e-ellipsis` can replace it for the preview span; the filter `input` needs `flex: 1; min-width: 0` only.
  - **Spacing of an icon in a line of text** (`editor/shell.tsx`, `cls_header_icon`: `margin-inline-end: 0.4em` between the column type's icon and the title, the one margin left, disabled with `no-margin`). `ui/icons.tsx` only sizes the icon. Candidate: elt/ui spaces an `.icon` followed by text (`.icon + *` or a gap on the inline text), so a title keeps its `e-ellipsis`.
  - **Missing justification comments**: `.oe-menu-item` (`gap`) doesn't say what was checked and why it fell short, as the rule requires.
- [ ] **Layout CSS in `ui/`** is exempt from the check but not audited either.
- [ ] **The Biome plugins** (`lint/`, listed in docs/md/hard-dont.md#enforcing-with-biome) cover `ui/`, `editor/` and `docs/src/`; the four CSS ones (`no-margin`, `theme-colors`, `motion-tokens`, `layout-css`) only `editor/` and `docs/src/`, as `ui/` implements the layout and the theme; `src/` gets only `out-prefix.grit` (it does the DOM work the others forbid), `tests/` none. Not checked: `style` attributes and objects (margins, layout CSS), named colors, observables whose kind the call doesn't show. Each `biome-ignore` in the code carries its reason.

## Found while rewriting the docs (not fixed)

- [ ] **The docs' small-screen nav** (`docs/src/app.tsx`) marks the open drawer with a class (`.open`), which ui-hard-dont.md rule 2 forbids (no plugin checks selectors), and draws its toggle as three bars by hand (no menu icon in `ui/icons.tsx`).

- [ ] `@attr` (custom elements) only works with legacy decorators; with `target: es2022` a property initializer silently shadows the decorated property. Docs tell users to use `declare` with no initializer and set defaults in `init()`.
- [ ] **Variance leftovers.** `param_soft(name, default)` is typed `Observable<NonNullable<T[K]>>` but a param can be removed from the URL later; `dispatch_object_editor_open`'s `o_value` is still `Observable<unknown>`, so callers declare `o<unknown>(…)`; `just bench` was not run after the variance change (one `instanceof` per write to a parent, one extra call per `tf`/`p`/`key` creation).
