## elt/ui

- [x] **Packed lines are children's borders, not a gap.** `seams="none|children|default|forced"` and `seam-color` replace `seamless` and the 1px gap (`row-rule`/`column-rule`, seam-colored background); `border` on a packed container is only the frame. Nested groups are cells of the container; the outermost radius is handed down. Docs: `docs/md/ui-layout.md#lines-between-the-children`. Open: `children` mode doesn't deduplicate across nested groups or in grids; a hidden first/last child of a framed container still doubles the line next to the frame (use `If`).
- [x] **A packed container without `border` lets its children draw the outline** (in every `seams` mode); any `border` (a frame, or `border="none"`, new) means they don't. Groups among the cells draw the outline only where it touches the outermost container's (`--e-out-*` flags, `ui/layout.css.tsx`). Docs: `docs/md/ui-layout.md#packed`. Open: the corners of a nested group's children that face a sibling group keep their own radius; no migration of existing frameless packed containers (`ui/search.tsx`, `ui/select.tsx`, docs nav, `code-example.tsx`) that may now want `border="none"`: to review visually.
- [ ] **Multi-select readability.** Re-check the selected-row treatment (tint surface + 3, docs/md/ui-theme.md#state) once a real multi-select widget exists: "reads fine in principle" isn't guaranteed to survive five selected rows on screen.
- [ ] **Overflow menu for bars.** A decorator that moves the actions that don't fit in a bar into a "…" menu as the window narrows (measured with a `ResizeObserver`, actions ordered by priority). Today the docs tell apps to choose the menu's actions when designing the bar (docs/md/ui-layout.md#bars).
- [x] **Buttons shrink below their label in a narrow row.** Buttons, toggles, checkboxes and radios are `flex-shrink: 0` in layout elements; `e-ellipsis` has `flex-shrink: 2` instead of 10000.
- [ ] **Editor bars vs. the emphasis model** (docs/md/ui-theme.md#emphasis). `editor/shell.tsx:310`: every editor's header line is tint-inverted, so nested editors stack several tint bands on one screen; a nested one should probably be a neutral surface. `editor/schema.tsx:1264`: the table header is on `tint-2`, which is furniture on tint; should be `neutral`. `editor/composite-toolbar.tsx:127`: a row with a button and a search field on a `neutral-1` band: acceptable as a secondary bar, check it once the above are settled.
- [ ] **Shadow tokens.** Add `shadow-cast` tokens (name favored, not locked) for overlay lift, and migrate `ui/dialog.tsx`/`ui/popup.tsx` off their hardcoded `rgba(...)` shadow/backdrop values onto them. The bevel system (`shadow-raise`/`-drop`) stays scoped to individual widgets.
- [ ] **Property browser column alignment.** Migrating off `<menu>` lost the icon/column alignment that `menu.tsx`'s grid/subgrid gave the property browser (`specs/object-editor.tsx`). `packed` is a flex mechanism and doesn't replace CSS grid.
- [ ] **ARIA composite widget keyboard model.** Popup rows carry `role="menu"`/`"menuitem"` or `role="listbox"`/`"option"` (`ui/select.tsx`), and the docs nav is a real `<nav aria-label="…">`. These roles formally require roving-tabindex arrow-key navigation and focus management, which isn't implemented. Keyboard resizing with `$resizable` (a focusable separator with arrow keys) belongs here too.
- [ ] **Appear/disappear motion rule.** Write the local rule: trigger conditions, duration/easing tokens, reduced-motion handling (partly covered by `prefers_reduced_motion()` in `ui/animation.tsx`).
- [ ] **Stale-name audit.** The old-name → new-name migration (now in `docs/md/migrating.md`) only inventoried Color-axis call sites; a dedicated pass is still needed to confirm no other stale Spacing/Layout references remain.

## Hard-don't follow-ups

- [x] **`sym_closed`.** Removed: a popup or dialog closed with no result (dismissed, or cancelled by the content) resolves `undefined`; `T` defaults to `boolean` and excludes `undefined`. `Deferred` renamed `Future`.
- [ ] **Alerts.** To design: they need a container (an alert host) to be `show`n in; how `show_alert` finds it is open.
- [x] **Layout CSS in `editor/`** audited against `docs/md/ui-hard-dont.md#check-before-you-write`. `.oe-column` (`flex: none`) removed: the strip's row of columns is a child of a scroll area, which elt/ui already keeps from shrinking (regression test in `tests/editor/shell.pw.ts`). Still open, in the next item.
- [ ] **Editor CSS that elt/ui could provide** (result of the audit above). Each is a class the editor has to write only because elt/ui has no equivalent; `ui/` changes need the user's go-ahead.
  - **Menu items and menu section titles** (`.oe-menu-item`, `.oe-menu-header`, `.oe-menu-danger`, and `text-align: start` of `.oe-text-fill` inside a button). The docs' own menu example (`ui-overlays.md`) is a column of `role="menuitem"` buttons whose labels elt/ui centers; every menu then needs start alignment and an icon/label gap. Candidates: style `[role="menuitem"]` start-aligned with a `nudge-4` gap in elt/ui; a section-title element for menus (small, faded, not selectable, no margin: `ui/typography.css.tsx` says an `<h3>` used as a menu title looks like an `<h3>`); a danger variant for buttons (red text and red hover, today `theme.colors.red.class_as_tint` plus `color: red`).
  - ~~**Column resize handle**~~ done: `$resizable` is in elt/ui (`ui/resizable.tsx`, docs/md/ui-widgets.md#resizable); the editor keeps only the `<table>` freeze. Keyboard resizing is not done (see the ARIA item).  (was `.oe-resizable-th`, `.oe-col-resize-handle`, `$column_resizable`. Nothing in it is specific to the editor: a resizable header cell for any table or `e-grid-row`. Candidate: move to elt/ui as a decorator.
  - ~~**Grid cell text**~~ done: cells of a packed container take the controls' font size and line height (docs/md/ui-layout.md#packed). (was `.oe-grid`: `font-size: formFontSize; line-height: 1.5` on every cell of every row). Form controls set their own font size, so any grid mixing text and fields misaligns. Candidate: elt/ui sets one font size and line height on the cells of a `packed` `e-grid-row`.
  - **Bounded scroll area** (partly done: objects with a fixed key set no longer have one, and packed cells inside a scroll area draw their focus ring inside themselves; `.oe-grid-scroll` stays for the windowed composites) (`.oe-grid-scroll`: `max-height: 24em; flex-grow: 1`). `max-height` takes only a boolean (`100%`), and `grow` sets `flex-basis: 0`, which collapses a scroll area in a column of no set height. Candidates: a `max-height` that takes a length (or a `--e-scroll-max-height` variable); a `grow` that keeps the content-sized basis.
  - ~~**Popup size**~~ done: `popup()` takes `min_width`/`max_width`/`max_height`, backed by the `popupMinWidth`/`popupMaxWidth`/`popupMaxHeight` theme settings; the room next to the anchor is now `--e-popup-room-*`. The editor and the date picker use them. (`.oe-popup-panel`: `min-width: 260px`, `max-width: min(90vw, 480px)`, `max-height: 70vh`). `ui/date.tsx` has the same `min-width: 260px`. The popup already caps its content at `--e-popup-max-width`/`-max-height` and `80vh`; what is missing is a way to ask for a minimum or a lower maximum (dialogs have `--e-dialog-max-width`). Candidate: `min-width`/`max-width` options on `popup`.
  - **Truncating text** (`.oe-text-fill`, the filter field and the preview in a button). `e-ellipsis` does most of it (`flex-grow`, `min-width: 0`, nowrap, ellipsis) but gives the text `flex-shrink: 10000`, meant for bars, and it does nothing for the left alignment inside a button (see the menu item candidate). Candidate: check whether `e-ellipsis` can replace it for the preview span; the filter `input` needs `flex: 1; min-width: 0` only.
  - **Missing justification comments**: `.oe-menu-item` (`gap`), `.oe-resizable-th` (`overflow`, `white-space`, `text-overflow`) and `.oe-col-resize-handle` (`5px`) don't say what was checked and why it fell short, as the rule requires.
